## 1. 失敗案例記錄表

一案例一列,新案例補在表尾。「情境」寫到服務+步驟(例:`B-3`= Service B 步驟 3;開場路由階段寫 `路由`)。

### 失敗類型枚舉

| 代碼 | 類型 | 說明 |
|------|------|------|
| F1 | 訪談被壓縮成獨白 | 提問後未停止等待輸入,自行推進多步(參 `dev/Reference_skill_modernization.md` §3 條 10) |
| F2 | persona 漂移 | 語氣偏離冷靜客觀(出現情緒鼓勵)、未用「您」、或長對話後流程規則失效 |
| F3 | 路由錯誤 | 求職階段推薦邏輯選錯服務,或 fast-track 誤判/漏判使用者意圖 |
| F4 | 術語違規 | 輸出使用 Glossary 禁止替代用法(如「STAR 原則」「職涯經歷」) |
| F5 | 幻覺代答 | 替使用者虛構未提供的履歷內容、經歷數據或回答 |
| F6 | 拒答句誤觸發 | 職涯相關問題被誤判為範疇外而觸發拒答句(或反向:範疇外未拒答) |

## 2. 記錄時機

| 誰 | 何時補一列 |
|----|-----------|
| 使用者(或代錄的 Claude session) | 實際使用 skill 後回報失敗——當下或 wrap-up 時補入 |
| 執行評測的 agent/session | 跑 `dev/Reference_eval_scenarios.md` 迴歸出現 FAIL 時,每個 FAIL 補一列(情境欄註明「評測」) |

記錄紀律:「使用者原話或現象」欄盡量引原文,不改寫;無法判定類型時先記 F7,迭代分析時再歸類。

## 3. 迭代流程

觸發條件(任一):
- 案例表累積 **≥5 筆未處理案例**;或
- **同一失敗類型出現第 2 次**(重複模式 = 系統性問題,不等湊數)。

流程:
1. **派工分析**:dispatch `Feedback Synthesizer` agent(`bench_agency-agents`,見 CLAUDE.md Active Agents 表),輸入本檔案例表,產出:失敗模式歸納 + 對 `MainFiles/` 對應檔(instructions.md / Service_*.md / Glossary.md 等)的具體修改建議(含 diff 預覽)。
2. **使用者裁定**:修改建議經使用者確認後才動 MainFiles(選項×利弊→建議格式呈報)。
3. **實施修改**:編輯對應檔案,commit 註明對應案例編號。
4. **迴歸驗證**:跑 `dev/Reference_eval_scenarios.md` 全部情境;有 FAIL → 回步驟 1(FAIL 本身補入案例表)。
5. **重新部署**:迴歸全 PASS 後依部署流程更新線上 skill;已處理案例在「#」欄打 ✅ 並註記處理 commit。
